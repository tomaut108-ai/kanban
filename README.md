# 課題・提出 Kanban — 演習6

教材「KanbanアプリでMVVMを学ぶ」の準備〜演習6を実装しました。

## 起動方法

```bash
cd kanban
flutter pub get
flutter run -d chrome
```

Asideで確認する場合は `flutter run -d web-server --web-port 8080` を実行し、表示されたローカルURLをAsideで開いてください。

## 実装範囲

- 未着手・作業中・完了の3列を表示する。
- 入力が空のときは追加ボタンを無効にする。
- 入力したタスクを未着手へ追加し、カードと件数を更新する。
- 追加後は入力欄を空にする。
- 左右の隣の列へタスクを移動し、各列の件数を更新する。
- 未着手には右ボタン、作業中には左右両方、完了には左ボタンを表示する。
- 追加・移動・編集・削除後に、タスク名と状態をJSON文字列で保存する。
- 起動時に保存データを読み込んでから画面を表示する。
- 編集ダイアログでは保存時だけ名前を変更し、キャンセル時は元の名前を保つ。
- 削除ボタンを押したカードのタスクだけを削除する。同名タスクも区別する。

## ファイルの役割

| ファイル | 役割 |
| --- | --- |
| `lib/model.dart` | Model：Taskのタスク名と状態 |
| `lib/view_model.dart` | ViewModel：一覧への追加・移動・編集・削除、変更通知、保存・読み込み |
| `lib/view.dart` | View：入力欄・ボタン・3列・編集ダイアログの表示 |
| `lib/main.dart` | ViewModelを作り、保存データを読み込んでアプリを起動 |

教材の演習1〜6をもとに授業の課題管理向けにアレンジし、整形、KanbanViewのconst指定、編集ダイアログ終了時のmounted確認、アイコンボタンのツールチップを補っています。

## 「考えてみよう」の回答

### 演習1

`model.dart` の `Task(this.title, [this.status = 0]);` で、statusを省略した場合の値を0（未着手）にしています。ViewModelの `add()` が `Task(text)` としてstatusを省略するので、追加されるタスクは未着手になります。

### 演習2

変更されるフィールドは `Task.status` です。各列は状態番号が一致するタスクを表示するため、変更通知を受けたあとにカードと件数が更新されます。

### 演習3

演習2の `move(Task t, int status)` が移動先を引数で受け取るためです。右は `s + 1`、左は `s - 1` を渡すだけで同じメソッドを使えます。

### 演習4

`main()` が `await vm.load()` の完了を待ってから `runApp()` を呼ぶため、最初の画面が作られる時点で復元済みのタスクがあります。この起動手順では `load()` 内の変更通知は不要です。

### 演習5

保存するまではTaskを変更せず、一時変数に入力内容を持たせることで、キャンセル時に元の名前を保てるためです。

### 演習6

共通の `save()` に変更通知とタスク一覧全体の保存をまとめているためです。削除後も同じメソッドを呼べます。

## 保存について

`SharedPreferencesAsync` を使用し、`kanban` キーにタスク名と状態のJSONを保存します。WebではブラウザのLocalStorageが保存先です。同じブラウザ・同じオリジン（プロトコル、ホスト、ポート）で再読み込みして確認してください。開発サーバーのポートが変わると、別の保存領域になります。固定ポートで確認する場合は以下を使用します。

```bash
flutter run -d web-server --web-port 8080
```

教材どおり、各操作は保存完了を待たずに画面を更新します。操作直後のタブ終了や保存失敗時の再試行・エラー表示は扱っていません。

## 検証

```bash
dart analyze
flutter test
flutter build web
```

`test/kanban_test.dart` は、空入力時のボタン無効、2件の追加、未着手の件数更新、入力クリア、他の2列が0件のままであることを検証します。

演習2・3のテストでは、2件のうち1件を未着手→作業中→完了→作業中→未着手と動かし、カードの表示列、件数、端のボタン制御、タスク名と総数の保持を確認します。新しいViewModelで保存データを読み込み、再起動相当での復元も確認します。

演習5・6の画面テストは、全列での編集・キャンセル・状態保持、同名タスクの片方だけの削除、全件削除後の復元を確認します。`test/persistence_test.dart` は初回の空データと各操作後のJSON保存・復元を確認します。

静的解析、テスト4件、Webビルドで検証しています。保存テストには公式のメモリ内ストレージを使用しており、実ブラウザのLocalStorage・タブ再読み込みは未確認です。

## アレンジの用途と目的

授業の課題・レポート・発表準備を管理し、作業の進み具合と提出状況を確認するためのアプリです。3列を「未着手・取り組み中・提出済み」にし、タイトル、入力ラベル・入力例、追加ボタン、移動先の文言、背景色を用途に合わせました。状態番号0・1・2とMVVMの分担は教材に沿っています。
